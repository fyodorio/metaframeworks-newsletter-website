[🎶 _In every life we have some trouble but when you worry you make it double..._ 🎶](https://www.youtube.com/watch?v=d-diB65scQU&list=PLYRq_7Yox1jDETeL_YgKUc8DXduCV9jA2&index=49)

I like Summer because even if it's sad and lonely around, the sun gives a lot of positivity. The last fortnight was quite calm and pleasant in webdev informational space, so I'm quite happy to share prevailingly positive news from the metaframeworks world and everything around.

## The Good

Babel team (_yes, Babel is still a thing, it still exists, and it's still not rewritten in Rust!_) had released [the first major version update in 8 years](https://babeljs.io/blog/2026/06/16/8.0.0/). It's cool to hear it not only evolves but still actively growing.

> Babel has grown from 1.7 million weekly downloads in 2018, to 651 million weekly downloads this week (Jun 2026). Babel has doubled its weekly download counts in the last year.

This is a big (_and breaking!_) modernization release which switches the tool into ESM mode, improves TypeScript support, and deprecates a lot of software archaeology, so check out [the migration notes](https://babeljs.io/docs/v8-migration/) carefully if you use that (_I do use it in [my personal metaframework project](https://gridmix.github.io), just saying, as it's not only Vite world around, you know_).

Preparing to release of new version (_as usual with long-lasting drum rolls_) Next.js team publishes a lot of interesting previews (_including a lot of unsolicited garbage, but still_). One thing that can actually be useful is [the instant navigations feature](https://nextjs.org/blog/next-16-3-instant-navigations).

> In Next.js 16.3, we are shipping new opt-in behaviors that let you have the best of both worlds: server-driven apps with instant navigations. You get the full benefits of a server, but navigations are instant like in a single-page app.

Interestingly, Waku, another RSC-oriented metaframework tool, [has this feature too](https://waku.gg/guides/navigation-prefetching#instant-navigation) (_which is also quite early and experimental there_). One thing that's unique to Waku though is the Slices feature the creator Daishi Kato [had recently elaborated on](https://newsletter.daishikato.com/p/waku-s-unique-feature-slices). The thing is quite nostalgic as it comes from [the Gatsby's history](https://www.gatsbyjs.com/docs/reference/built-in-components/gatsby-slice/).

## The Bad

As I hinted already, there's not much of a drama these days in the metaframeworks world, except for the drastically annoying and never ending AI bangaranga, which, [as the guys from HTML All The Things podcast confirmed](https://www.htmlallthethings.com/podcast/would-you-risk-your-job-to-oppose-ai-debate), is in 99% of the cases caused by the ubiquitous desire to please our CEOs, so it all is not real anyway, we're good.

One worrying thing that caught my attention the last week though was [the observation of Filippo Valsorda](https://words.filippo.io/vuln-reports/) on devaluing of security reports which puts us all under quite a danger. I really hope the former and the latter (_going hand in hand_) won't spoil the software development party for us anytime soon, but just in case, be warned and prepared: some things are not what they seem!

## The Noteworthy

While some products move slowly and stick to unrisky stability, the other tools prefer to run fast, break things, try waters, and such.

The release candidate of the new era of TypeScript — version 7 with Go-based compiler — is [there for testing](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0-rc/). I'm sure it won't take MicroSoft too much time to switch as the preparation and testing phases were running for quite a long time already.

Deno team also is not stopping because squeezing the orgchart and stuff, so [their new release 2.9](https://deno.com/blog/v2.9) contains a lot of new cool features for the platform, including the possibility to quickly turn your metaframework-based web app into a cross-platform desktop application [without using Electron or Tauri](https://docs.deno.com/runtime/desktop/). The release also includes major performance improvements, enablements for quick migration from npm, pnpm, yarn, and Bun (_including preserving the lockfile state!_), testing and security improvements, smaller standalone binaries, and other awesomeness which makes switching to Deno quite enticing.

> Believe it or not, the changes listed above still don’t tell you everything that got better in 2.9. You can view the [full list of pull requests merged in Deno 2.9 on GitHub](https://github.com/denoland/deno/releases/tag/v2.9.0).

React Router [got it's new major version 8](https://remix.run/blog/react-router-v8) (_declared "boring" but we all know the drill with the stuff published on remix.run website_). The blogpost contains a lot of nostalgia for the passed v7 epoch so I highly recomment to skim through it. And the positive side — nothing should break in fact, unless [you're living in a forest](https://reactrouter.com/upgrading/v7).

Astro team published [its new major version (_7_) too](https://astro.build/blog/astro-7/), with more Rust-ification for this Rust-greedy metaframeworks world. As usual I test it on this newsletter website so that you wouldn't have to, please let me know in case of any issues! 🤞🏼

Vite got slowed down by the recent publicity work (_or maybe just because there's no VC rush anymore_) and just came up with [the first new minor release](https://vite.dev/blog/announcing-vite8-1) since March — the new version celebrates growing weekly downloads number (_still surprisingly minuscule fraction of Babel's metrics though_ 😏), provides experimental support for [bundled dev mode](https://github.com/vitejs/vite/discussions/22746), and lots of other technical improvements. The coolest thing I read in the release notes was definitely this excerpt:

> In the output bundle, the import statement of a chunk includes the hash of that chunk. This is to ensure the new chunk is loaded if the chunk content has changed. However, this also causes the hash of the chunk importing the changed chunk to change, cascading the change to all the chunks that import the changed chunk transitively.

That's probably quite similar to what my wife hears when I tell her about Angular's dependency injection, but still, [the actual feature of chunk import maps](https://vite.dev/blog/announcing-vite8-1#experimental-chunk-import-map) is quite rad.

RedwoodSDK [now supports Vite 8 too](https://github.com/redwoodjs/sdk/releases/tag/v1.5.0) in their latest v1.5.0, with backward compatibility to Vite 6+ (_kudos for that!_), but not only that — the team is quite active on new technical updates, like new navigation pending suspense feature [in v1.4.0](https://github.com/redwoodjs/sdk/releases/tag/v1.4.0), or client-side optimizations and improvements [in v1.3.0](https://github.com/redwoodjs/sdk/releases/tag/v1.3.0).

[Vike changelog](https://github.com/vikejs/vike/blob/main/packages/vike/CHANGELOG.md) got some weird series of bumps in a single bundle but as the matter of fact, it was quite interesting to read about the way guys went during the last year.
